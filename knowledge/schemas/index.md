# schemas

- [Architecture schema][sokf:schema-architecture] - An architecture introduces a system and shows, in a hierarchy of diagrams, its context, its subsystems and their parts, its contracts, its flows, where it runs, and its technology.
- [Coding standard schema][sokf:schema-coding-standard] - The rules for the code of one language, grouped by topic, one rule per item.
- [Contract schema][sokf:schema-contract] - The interface and the behaviour that a building block promises to its users, for any kind of interface.
- [Design schema][sokf:schema-design] - How one building block is built, for a developer who changes its code: the ideas it rests on, its modules, how they work together, the interfaces between them, its data, the rules across its modules, its limits, the rules that a change keeps, and the decisions behind it.
- [Documentation standard schema][sokf:schema-documentation-standard] - A documentation standard sets the rules for one kind of documentation, in sections by topic after an opening, a contents list, and an optional order of precedence.
- [Formats schema][sokf:schema-formats] - A formats document describes a file of shared line formats, so that a schema author can bind a format by name without reading the file.
- [Glossary schema][sokf:schema-glossary] - The terms that the documents of a knowledge store use, each defined once.
- [Issue schema][sokf:schema-issue] - An issue records one piece of work (a feature, a bug, or a chore): what the work asks for, the plan for doing it, and its outcome.
- [JSON Schema sidecar schema][sokf:schema-json-schema] - A JSON Schema sidecar sits beside a JSON Schema file and tells a developer, in one paragraph, what the JSON output is and how the file is kept current.
- [Non-goals schema][sokf:schema-non-goals] - What the system that a knowledge store describes doesn't do, and why.
- [Penetration test statement of work schema][sokf:schema-pentest-sow] - The statement of work for one penetration test of one customer, written from an interview, with the executive summary, scope, testing approach, roles, dependencies, deliverables, pricing, timeline, acceptance, change control, and terms.
- [Recipe schema][sokf:schema-recipe] - A recipe explains how to do one task on the project: an opening that says what the task is and when to do it, a contents list, and one section for each step, in order.
- [Stories schema][sokf:schema-stories] - A Stories document holds the stories for one user goal, and each story links the contracts that deliver it.
